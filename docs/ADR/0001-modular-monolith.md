# ADR 0001：采用模块化单体（Modular Monolith）

- **状态：** 已接受  
- **日期：** 2026-11-23  

## 背景

GNI 需要采集、处理、分析、指标与报告等多能力。可选微服务拆分或单体模块化。

## 决策

采用 **Modular Monolith**：单部署单元、包级模块边界（`sources` / `ingestion` / `processing` / `analysis` 等），异步任务在进程内或简单调度器中执行。

## 理由

- MVP 团队规模小，微服务运维成本过高  
- 事务与一致性更简单（PostgreSQL）  
- 仍可通过清晰接口为未来拆分留空间  

## 后果

- 须纪律执行模块边界，避免「大泥球」  
- 暂不引入 Kafka / 多服务网格  

## 备选

微服务、多仓库：否决（过早优化）。
