# 竞品与参考案例分析

**说明：** 本节依据**公开产品介绍与功能定位**作定性比较，不代表对竞品内部模型准确率或性能做过独立测试。  
**访问/整理日期：** 2026-11-23  
**用途：** 提炼 GNI 设计原则，非照搬功能清单。

---

## 1. 拆解总表

| 产品 | 重点研究 | GNI 借鉴点 | 不照搬 |
|------|----------|------------|--------|
| Signal AI | 结构化分析、检索、证据回溯、Ask AIQ 类工作流 | 先检索与结构化，再生成解释 | 企业声誉/品牌风险主场景 |
| GDELT | 多语言新闻、文章/实体/主题/事件分层 | 数据对象分层与多语言采集思路 | 政治事件编码 ≠ GNI 媒体叙事事件 |
| Media Cloud | 媒体集合、国家/语言/时间过滤、关注度趋势 | 来源集合与长期叙事研究 | 不完全等同官方来源治理 |
| Dataminr | 事件发现、多源交叉验证 | 重大信号需持续佐证 | 实时多模态规模远超 MVP |
| Meltwater | Mention Volume、SOV、Sentiment、告警 | 指标与 Dashboard 组织 | 品牌声量 ≠ 国家叙事；须控转载放大 |
| ACLED | 独立可解释指数方法论 | 先独立指标，再考虑合成 | 冲突指数公式不可直接套用 |

---

## 2. 分产品要点

### 2.1 Signal AI

- **公开定位（定性）：** 企业媒体情报、分类、检索、分析、告警与生成式问答工作流。  
- **借鉴：** Insight 可回溯来源；Agent 建立在可验证查询工具之上。  
- **边界：** GNI 研究国家/媒体叙事，非品牌声誉。  
- **参考：** 以厂商公开站点与产品页为准（具体 URL 实施时记录并更新日期）。

### 2.2 GDELT

- **借鉴：** 文章、事件、实体、主题独立建模；采集与分析管线分层。  
- **边界：** 须自定义 GNI 事件边界，不能直接等同 GDELT 事件编码。

### 2.3 Media Cloud

- **借鉴：** 研究媒体集合而非只看单篇；主题占比与跨期变化作为基础视图。  
- **边界：** GNI 额外强调官方属性、所有权与编辑独立性治理。

### 2.4 Dataminr

- **借鉴：** 新事件需后续来源持续佐证；单篇不足以定重大信号。  
- **边界：** 实时多模态能力不在 MVP。

### 2.5 Meltwater

- **借鉴：** 指标服务研究问题；展示趋势、分布与样本量。  
- **边界：** 转载放大必须用 Unique Story / Original / Syndicated 分计。

### 2.6 ACLED

- **借鉴：** 独立指标 → 可解释、可版本化合成指数。  
- **边界：** 综合指数仅 Phase 3 评估；MVP 不做黑盒总分。

---

## 3. 推荐拆解顺序（研究用）

Media Cloud → GDELT → Signal AI → ACLED → Dataminr → Meltwater

---

## 4. GNI 差异化（相对上述参考）

1. 来源治理更明确（官方属性、控制程度、编辑独立性 + 证据）  
2. 情感 / 目标对象立场 / 框架 / 证据严格分离  
3. 事件与叙事分层建模（Phase 2）  
4. 长期基线比较（条件成熟后）  
5. 证据驱动：结论回溯文章、段落、来源与分析版本  

---

## 5. 对 Phase 1 的直接设计原则

1. 先结构化入库与可检索，再生成报告解释  
2. Dashboard 按研究问题组织，不堆单一「舆情分」  
3. 所有占比公开分母；质量面板与舆情结论分离  
4. Agent（Phase 3）不得绕过数据库事实与证据校验
