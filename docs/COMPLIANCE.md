# 合规与来源准入（COMPLIANCE）

**用途：** 内部研究默认前提下的来源接入检查清单与数据保存原则。  
**免责声明：** 本文不构成法律意见；具体合规须按来源、服务器所在地、用户所在地与用途评估。

---

## 1. 使用边界

| 项 | MVP 默认 |
|----|----------|
| 用途 | 内部研究与分析 |
| 对外分发全文 | **不默认**允许 |
| 公开报告 | 优先摘要、结构化分析结论与**原文链接** |
| 商业多租户转售内容 | 不做 |

---

## 2. 来源接入前检查表

每个候选来源在激活前完成并归档：

| # | 检查项 | 记录字段 | 通过标准（摘要） |
|---|--------|----------|------------------|
| 1 | 识别来源主体与国家 | organization / country | 可唯一定位 |
| 2 | 服务条款 / 版权页 | terms_url、摘录要点 | 已阅读并记录限制；不明则 pending/restricted |
| 3 | robots.txt 检查 | robots_checked_at、结论摘要 | 已检查；**不作为法律授权** |
| 4 | 访问方式 | access_method | 优先 rss/api；web 须结构稳定 |
| 5 | 登录 / 付费墙 | notes | 存在则默认不进 MVP |
| 6 | 请求频率限制 | notes / config | 有保守速率上限 |
| 7 | 内容保存与再分发限制 | compliance_status | 与保存策略一致 |
| 8 | 个人信息风险 | notes | 高风险则限制字段或排除 |
| 9 | 分类证据 | evidence_url、confidence | 有依据可复核 |
| 10 | 审核人与时间 | reviewed_by、reviewed_at | 已签字式记录 |

**结论枚举：** `pending` / `allowed_internal` / `restricted` / `blocked`

---

## 3. 数据保存原则

1. 保存必要元数据、URL、分析所需必要正文片段  
2. **不默认**永久保存全部原始 HTML  
3. 正文与证据片段设访问权限与保留策略（具体天数 TBD，Phase 1 配置化）  
4. 公开材料避免未经许可的大规模全文转载  
5. 分析证据优先短引用 + 原文链接  

---

## 4. 采集行为约束

- 遵守来源合理速率；失败退避重试  
- 默认 User-Agent 标识研究爬虫；若官网 WAF 对非浏览器 UA 一律 403，允许在 Source Registry `config.user_agent` 使用浏览器兼容 UA，并同时发送 `X-GNI-Client` 研究标识（须记入 notes，禁止用于登录墙/付费墙）  
- 禁止绕过技术访问控制（登录墙、付费墙、明确反爬对抗）  
- 单源条款冲突时：暂停该源，不「悄悄换 Web 硬爬」凑数  

---

## 5. 俄 / 印等高风险备注

- **俄罗斯：** 跨境可达性、镜像可用性、条款与出口管制类风险需个案评估；未通过则保持 candidate  
- **印度：** 多语言站点与邦/联邦机构差异大；逐源核验，不批量假设 RSS 可用  

---

## 6. 与报告的关系

正式报告不得粘贴大段受版权保护正文作为「产品内容」对外发布；内部研究视图可按 `allowed_internal` 展示必要片段，并保留审计日志（Phase 1 实现）。
